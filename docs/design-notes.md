# 设计笔记：为什么这样做

这份笔记记录几个不显然的决定，方便以后维护或 review。

## 1. 为什么是「侧边栏面板」而不是浮层/装饰

宿主提供的增量席位里，能容纳「主要参数 + 3 天预报 + 24 小时」而不挤占对话区的只有
`sidebar.panellist`（图标）+ `main`（页面）：

- `conversation.composer.dock` 只有一行高度，放不下参数表；
- `shell.overlay` 是浮层，会和别的插件的浮层、宿主动效抢位置；
- `main` 的 key 是开放的，用自己的 key 就只是「多一页」，不替换 `conversation`。

代价是 `main` 的 `replaceRisk` 标着 `shadows-shipped-ui`——但那只在**复用已有 key**时成立。
自定义 key 是纯增量，`Slots` 的 occupants 里可以看到它与宿主页面并列。

## 2. 为什么 Host 半侧是空的

`index.js` 只导出 `apply(){}`。原因：

- 定位与天气都是公开 HTTPS 接口，浏览器 `fetch` 直连即可（CORS 已实测为 `*`），
  不需要 Host 的网络权限、不需要 IPC 往返；
- 少一个 Host 服务就少一处与其它插件/版本耦合的地方；
- 缓存写 `localStorage`，天然按页面隔离，不需要 DSH storage 服务。

如果将来要做「到点推送预警」，那才需要 Host 侧（定时器 + 通知），届时再加。

## 3. 定位为什么是「多源竞速 + 来源可见 + 可覆盖」

实测经验（见追风项目）：单一 IP 定位服务会限流、会被区域网络拦、会把代理出口当成所在地。
所以：

- 三个 https 源并发，谁先给出合法经纬度用谁；解析函数负责拒绝 `lat: 999` 这类脏数据；
- 面板副标题永远写清「网络定位 · <IP>」或「手动选择的位置」；
- 一键切到系统定位或手动搜索城市，覆盖值持久化。

逆地理编码只用于「起名字」，失败时依次退到 IP 源的 `city`、再到 `36.06°N 120.38°E`，
绝不会因为起不到名字而拿不到天气。

## 4. 时间为什么不用 `Date`

Open-Meteo 在 `timezone=auto` 下返回的是**当地**的 `YYYY-MM-DDTHH:mm`（无偏移后缀）。
把它当字符串比较，就能得到「当前小时之后的 24 个逐时点」，既不依赖运行环境时区，
也不会在夏令时切换当天错位。只有星期/日期标签需要换算，那里用 `Date.UTC` + `timeZone:'UTC'` 固定住。

## 5. 缓存与失败语义

| 阶段 | 命中缓存 | 未命中 | 失败时 |
| --- | --- | --- | --- |
| 定位 | 6 小时内直接复用 | 三源竞速 | 抛出 `locate` 错误，面板提示手动搜索 |
| 预报 | 10 分钟内直接渲染并跳过网络 | 单请求拉全量 | 有旧数据就继续显示旧数据 + 错误条，没有就显示重试 |

「先渲染缓存再校验」让重开面板几乎无等待；`AbortController` 保证连续点刷新时只有最后一次生效。

## 6. 样式的边界

- 全部 CSS 在面板自己渲染的 `<style>` 中，选择器带 `dshw-` 前缀；
- 只用 `--dsw-alias-*` 令牌并给浅色兜底，令牌改名最多影响观感，不会让面板崩掉；
- 天气插画用固定色，因为它是「内容」而不是「外壳」，深浅色下都应保持同样的辨识度。

## 7. 为什么提交构建产物
Harness 的浏览器模块必须是**单个** `client.js`（多文件需要 `require.async` 分块 + 构建器支持）。
为了既能单文件交付、又能让源码可测试，采用「源码 ESM + 零依赖拼接」：

- `src/lib/*.js` 是真 ESM，`node:test` 可直接 import；
- `scripts/build.mjs` 去掉 import/export 后包进 `window.__ModuleLoader__.load(...)`；
- 构建脚本会断言没有残留的 import/export，`node --check` 再兜一层语法；
- `test/bundle.test.mjs` 在 `vm` 沙箱里真正启动产物并检查注册行为。

## 8. 国内数据源怎么选的

要求「预警更准」，所以先找国内官方源。逐条实测（都在浏览器里带 `Origin` 请求过）：

| 候选 | 结果 | 结论 |
| --- | --- | --- |
| `www.nmc.cn/rest/findAlarm` | 200，`ACAO: *`，296~298 条全国生效预警，含标题/级别/时间/详情链接 | **采用** |
| `typhoon.nmc.cn/…/list_default`、`view_<id>` | 200，`ACAO: *`，JSONP（`cb(({…}))`） | **采用**（自行剥壳） |
| `weather.cma.cn/api/weather/view` | 200，有 `alarm` 字段但本站实测为空，且站号 API 需 cookie | 仅作参考，未采用 |
| `product.weather.com.cn/alarm/grepalarm_cn.php` | 需要 Referer 才 200，且无 CORS | 浏览器不可用 |
| 第三方聚合（和风/心知/tianqiapi 等） | 需要 Key | 不符合「无 Key」 |

关键决定：**不为国内源引入 Host 代理**。两个官方接口都带 `ACAO: *`，浏览器可直连；
这样插件保持纯客户端，不需要 Host 网络权限，也不会与其它插件抢端口或路由。

预警的过滤方式：接口给的是全国流，只能按标题匹配地名（例：`内蒙古自治区呼伦贝尔市气象台…`）。
先按市名匹配，没有匹配再退回省名，并把「省」级命中标记为 `scope: 'region'`，UI 上如实标注。

## 9. 启动提醒为什么放在 `shell.overlay`

面板只有在用户点开时才会挂载，而「打开 DSH 就提醒」必须在没人打开面板时也能发生。
`shell.overlay` 是 frame-wide 浮层，页面启动即渲染，所以提醒注册在那里；面板未打开时它
返回 `null`，不占任何位置。

两个细节：

- 该图层由宿主声明为 **click-through**（说明里写明「entries opt back into pointer events」），
  所以弹窗根节点必须显式 `pointer-events:auto`，否则点不到按钮；
- 去重分两层：`localStorage` 按「日期 + 签名」记录确认；签名 = 排序后的预警 id 列表 + 是否下雨。
  于是同一天不会重复打扰，而**新增预警**会改变签名，再次提醒。
- 数据与面板共用同一个 store：启动只发一轮请求，面板打开不再重复拉取。

## 10. 台风底图：离线海岸线 + 官方图入口

最初只画经纬网，可读性一般。评估过四条路：

| 方案 | 结论 |
| --- | --- |
| 在线瓦片（OSM / Carto / 高德） | 需额度/条款，国内访问与被限风险，且桌面端 Referer 不受控 → 不做默认 |
| 天地图 WMTS | 国内最合规，但需要用户申请 key → 留作可选（未实现） |
| 官方路径图 `<img>` | 不可交互、URL 每期变化 → 只做成「查看官方路径图」入口 |
| **离线海岸线矢量（采用）** | 无网络、无 key、无 CORS、无额度、离屏可用 |

实现方式：

- 数据：Natural Earth `ne_50m_land`（公有领域，无需授权）。`scripts/build-basemap.mjs` 在**构建期**
  做四步处理：裁剪到 90–180°E / -12–48°N（Sutherland–Hodgman）→ RDP 抽稀 0.05° →
  坐标取整到 0.01° → 丢弃过小多边形。产物 `src/ui/basemap-data.js` **36 KiB**（124 环、约 3.4k 点），
  原始 GeoJSON 1.6 MB 只存在于被 gitignore 的 `.cache/`。
- 渲染：与轨迹共用同一个等距圆柱投影，一个 `<path>` 画所有陆地；环按 bbox 与当前视野求交，
  视野外的整环直接跳过。SVG 的 viewBox 会自动裁剪跨出画面的部分，所以不需要手动裁多边形。
- 只画**陆地填充 + 海岸线**，不画国界：既避免边界表示争议，也正好满足「台风在哪、往哪走」的参照需求。
- 概化说明：1:50m 数据 + 0.05° 抽稀意味着海岸线有约 1–2 km 的概化，紧贴海岸的城市点（如沿海城市市区）
  可能落在水面一侧；参考城市本来就是标记点，不影响判读。

「查看官方路径图」按钮直接打开中央气象台台风网（`https://typhoon.nmc.cn/web.html`）。该站是 Leaflet
单页应用、没有稳定的按台风深链，也没有稳定的静态路径图 URL（产品图文件名带期次时间戳），所以只做入口、
不内嵌图片——这样也不会把官方图片版权与失效风险带进插件。

投影把经度乘 `cos(中心纬度)` 做横向压缩，避免高纬度被拉宽；风圈按 km 换算成经纬度半径后
分别画 `rx/ry`，所以看起来是椭圆而不是圆——这与真实球面距离一致。

一个实测坑：**最新定位点常常没有预报场**（`point[11]` 为 `null`，预报随下一期警报下发），
所以解析时回溯到最近一个带预报的定位点，并把预报基准时间显示出来。
